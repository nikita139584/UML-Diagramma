# UML-діаграма класів Backend

## 1. Загальний опис

UML-діаграма класів описує структуру backend частини веб-застосунку **«Кулінарний блог»**.

Система реалізована на основі **ASP.NET Core MVC**, використовує **Entity Framework Core** для роботи з базою даних та **SQL Server** як систему керування базами даних.

Архітектура backend поділена на декілька логічних рівнів:

| Рівень | Призначення |
|---|---|
| **Controllers** | Приймають HTTP-запити та передають їх до відповідних сервісів |
| **Services** | Містять бізнес-логіку застосунку |
| **Interfaces** | Визначають контракти для роботи з даними |
| **Repositories** | Реалізують доступ до даних |
| **Models** | Представляють основні сутності предметної області |
| **AppDbContext** | Забезпечує взаємодію Entity Framework Core із базою даних |
| **SQL Server** | Зберігає дані застосунку |

Загальна структура взаємодії:



Controller
    ↓
Service
    ↓
Repository Interface
    ↓
Repository
    ↓
AppDbContext
    ↓
SQL Server



---

# 2. Controllers

Контролери є точкою входу для HTTP-запитів. Вони приймають запити від клієнтської частини та передають виконання відповідним сервісам.

| Controller | Призначення | Основний Service |
|---|---|---|
| `AuthController` | Реєстрація та авторизація | `AuthService` |
| `RecipesController` | Перегляд, пошук і фільтрація рецептів | `RecipeService` |
| `BlogController` | Керування блогами | `BlogService` |
| `PostController` | Створення, редагування та видалення постів | `PostService` |
| `CommentController` | Робота з коментарями | `CommentService` |
| `RatingController` | Оцінювання рецептів | `RatingService` |
| `AdminController` | Адміністративне керування | `UserService`, `PostService`, `CommentService` |

## 2.1. AuthController

`AuthController` відповідає за функції реєстрації та авторизації користувачів.

Основні функції:

- реєстрація нового користувача;
- авторизація користувача;
- передача даних до `AuthService`;
- обробка результату авторизації.

**Зв'язок:**



AuthController → AuthService



---

## 2.2. RecipesController

`RecipesController` відповідає за роботу з рецептами.

Основні функції:

- перегляд списку рецептів;
- перегляд окремого рецепта;
- пошук рецептів;
- фільтрація;
- отримання популярних рецептів.

**Зв'язок:**


RecipesController → RecipeService



---

## 2.3. BlogController

`BlogController` відповідає за роботу з блогами користувачів.

Основні функції:

- створення блогу;
- перегляд блогу;
- редагування власного блогу.

**Зв'язок:**



BlogController → BlogService



---

## 2.4. PostController

`PostController` відповідає за керування постами.

Основні функції:

- створення посту;
- редагування посту;
- видалення посту;
- перевірка прав користувача на редагування власного контенту.

**Зв'язок:**



PostController → PostService



---

## 2.5. CommentController

`CommentController` відповідає за роботу з коментарями.

Основні функції:

- додавання коментаря;
- валідація коментаря;
- збереження коментаря;
- видалення коментаря за відповідних прав доступу.

**Зв'язок:**


CommentController → CommentService



---

## 2.6. RatingController

`RatingController` відповідає за оцінювання рецептів користувачами.

Основні функції:

- приймання оцінки користувача;
- збереження оцінки;
- передача даних до `RatingService`;
- оновлення рейтингу рецепта.

**Зв'язок:**

RatingController → RatingService


---

## 2.7. AdminController

`AdminController` відповідає за адміністративні операції.

Основні функції:

- перегляд користувачів;
- блокування користувачів;
- модерація постів;
- модерація коментарів;
- виконання операцій, доступних лише адміністратору.

**Зв'язки:**


AdminController → UserService
AdminController → PostService
AdminController → CommentService


---

# 3. Services

Services містять основну бізнес-логіку застосунку та використовуються контролерами для виконання операцій.

| Service | Призначення |
|---|---|
| `AuthService` | Реєстрація та авторизація користувачів |
| `RecipeService` | Робота з рецептами, пошук, фільтрація та популярні рецепти |
| `BlogService` | Створення та редагування блогів |
| `PostService` | Створення, редагування та видалення постів |
| `CommentService` | Додавання, перевірка та видалення коментарів |
| `RatingService` | Збереження оцінок та оновлення рейтингу |
| `UserService` | Керування користувачами та їх блокування |

---

## 3.1. AuthService

`AuthService` містить бізнес-логіку, пов'язану з реєстрацією та авторизацією користувачів.

Основні функції:

- перевірка даних користувача;
- реєстрація;
- авторизація;
- взаємодія з ASP.NET Core Identity.

---

## 3.2. RecipeService

`RecipeService` містить бізнес-логіку роботи з рецептами.

Основні функції:

- отримання рецептів;
- пошук;
- фільтрація;
- отримання популярних рецептів;
- перевірка даних перед виконанням операцій.

---

## 3.3. BlogService

`BlogService` відповідає за бізнес-логіку роботи з блогами.

Основні функції:

- створення блогу;
- отримання інформації про блог;
- редагування блогу;
- перевірка прав користувача.

---

## 3.4. PostService

`PostService` відповідає за бізнес-логіку постів.

Основні функції:

- створення посту;
- редагування посту;
- видалення посту;
- перевірка прав користувача.

---

## 3.5. CommentService

`CommentService` відповідає за бізнес-логіку коментарів.

Основні функції:

- додавання коментаря;
- перевірка даних;
- збереження коментаря;
- видалення коментаря.

---

## 3.6. RatingService

`RatingService` відповідає за роботу з оцінками рецептів.

Основні функції:

- збереження оцінки;
- перевірка оцінки;
- розрахунок або оновлення рейтингу рецепта.

---

## 3.7. UserService

`UserService` використовується для адміністративних операцій над користувачами.

Основні функції:

- отримання списку користувачів;
- перегляд інформації про користувача;
- блокування користувача;
- адміністративне керування користувачами.

# 5. Repositories

Repositories реалізують відповідні інтерфейси та відповідають за доступ до даних.

Основна структура:

IRecipeRepository
        ↓
RecipeRepository

IBlogRepository
        ↓
BlogRepository

IPostRepository
        ↓
PostRepository

ICommentRepository
        ↓
CommentRepository

IRatingRepository
        ↓
RatingRepository

IUserRepository
        ↓
UserRepository


Репозиторії взаємодіють із `AppDbContext`, який забезпечує роботу з Entity Framework Core.


Repository
    ↓
AppDbContext
    ↓
SQL Server


Таким чином, бізнес-логіка сервісів не повинна напряму працювати з SQL Server.

# 6. Models

Models представляють основні сутності предметної області.

| Model | Призначення |
|---|---|
| `User` | Користувач системи |
| `Blog` | Блог користувача |
| `Post` | Публікація в блозі |
| `Recipe` | Рецепт |
| `Comment` | Коментар до рецепта |
| `Rating` | Оцінка рецепта |

---

## 6.1. User

`User` представляє користувача системи.

Користувач може мати одну з таких ролей:

| Роль | Опис |
|---|---|
| **Guest** | Неавторизований користувач |
| **User** | Зареєстрований користувач |
| **Author** | Користувач, який веде блог |
| **Administrator** | Користувач із розширеними правами |

Авторизовані користувачі можуть створювати контент, коментувати та оцінювати рецепти. Адміністратор має додаткові права для керування користувачами та модерації контенту.

---

## 6.2. Blog

`Blog` представляє блог користувача.

Блог використовується для розміщення постів.

Зв'язок:


User 1 ───── * Blog


Один користувач може мати пов'язаний із ним блог, а блог містить публікації.

---

## 6.3. Post

`Post` представляє публікацію в блозі.

Основні операції:

- створення;
- редагування;
- видалення.

Зв'язок:


Blog 1 ───── * Post


Один блог може містити багато постів.

---

## 6.4. Recipe

`Recipe` представляє рецепт у системі.

Рецепти можуть:

- переглядатися;
- шукатися;
- фільтруватися;
- оцінюватися користувачами.

Також система формує список популярних рецептів.

---

## 6.5. Comment

`Comment` представляє коментар користувача до рецепта.

Основні зв'язки:

User   1 ───── * Comment
Recipe 1 ───── * Comment


Один користувач може залишати багато коментарів, а один рецепт може мати багато коментарів.

---

## 6.6. Rating

`Rating` представляє оцінку рецепта користувачем.

Основні зв'язки:


User   1 ───── * Rating
Recipe 1 ───── * Rating

Після додавання оцінки рейтинг рецепта оновлюється.

---

# 7. Зв'язки між Models

Основні зв'язки між сутностями системи:

| Зв'язок | Тип | Опис |
|---|---|---|
| `User → Blog` | `1 : *` | Користувач пов'язаний із блогом |
| `Blog → Post` | `1 : *` | Блог може містити багато постів |
| `User → Comment` | `1 : *` | Користувач може залишати багато коментарів |
| `Recipe → Comment` | `1 : *` | Рецепт може мати багато коментарів |
| `User → Rating` | `1 : *` | Користувач може залишати оцінки |
| `Recipe → Rating` | `1 : *` | Рецепт може мати багато оцінок |

Візуально:

User
 ├──────── 1 : * ──────── Blog
 │                           │
 │                           │ 1 : *
 │                           ↓
 │                          Post
 │
 ├──────── 1 : * ──────── Comment
 │                           ↑
 │                           │
 │                         Recipe
 │                           │
 └──────── 1 : * ──────── Rating

# 8. AppDbContext

`AppDbContext` є контекстом **Entity Framework Core**.

Він забезпечує взаємодію між моделями застосунку та базою даних.

Основний потік:


Models
   ↓
AppDbContext
   ↓
SQL Server


Репозиторії використовують `AppDbContext` для отримання та збереження даних.

---

# 9. SQL Server

**SQL Server** використовується як база даних веб-застосунку.

У базі даних зберігається інформація про:

- користувачів;
- блоги;
- пости;
- рецепти;
- коментарі;
- оцінки.

Загальна схема роботи з базою:


Controllers
     ↓
Services
     ↓
Interfaces
     ↓
Repositories
     ↓
AppDbContext
     ↓
SQL Server


---

# 10. Загальний Data Flow

Під час перегляду рецепта запит проходить через такі компоненти:


Client
   ↓

   ↓
RecipeService
   ↓
IRecipeRepository
   ↓
RecipeRepository
   ↓
AppDbContext
   ↓
SQL Server


Після отримання даних відповідь повертається назад до клієнта.

Для створення нового посту використовується такий потік:


Client
   ↓

   ↓

   ↓
IPostRepository
   ↓
PostRepository
   ↓
AppDbContext
   ↓
SQL Server


Перед збереженням система повинна перевірити коректність даних та права користувача.

## 10.3. Додавання коментаря

   ↓

   ↓
AppDbContext
   ↓

Після успішного збереження коментар відображається на сторінці рецепта.

---

## 10.4. Оцінювання рецепта

   ↓

   ↓

   ↓

Після збереження оцінки система оновлює рейтинг рецепта.

# 12. Висновок

UML-діаграма демонструє розподіл відповідальності між основними компонентами backend системи **«Кулінарний блог»**.

| Компонент | Відповідальність |
|---|---|
| **Controllers** | Обробка HTTP-запитів |
| **Services** | Реалізація бізнес-логіки |
| **Interfaces** | Визначення контрактів |
| **Repositories** | Робота з даними |
| **Models** | Представлення сутностей системи |
| **AppDbContext** | Робота Entity Framework Core з БД |
| **SQL Server** | Зберігання даних |

Така структура дозволяє розділити відповідальність між компонентами системи, спрощує тестування, підтримку та подальший розвиток backend частини застосунку.
